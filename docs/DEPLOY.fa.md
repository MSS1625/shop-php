# 🚀 دیپلوی دیجی‌شاپ روی VPS — راهنمای قدم‌به‌قدم (با سرور رایگان)

> این راهنما نسخهٔ فارسی است؛ نسخهٔ انگلیسی: [`docs/DEPLOY.md`](DEPLOY.md)
>
> از v2.17.0، کل فروشگاه با استک پروداکشن (app + web + db + caddy) روی هر سرور
> لینوکسی با دو دستور بالا می‌آید — با HTTPS خودکار. چیزی که لازم دارید:
> **یک VPS**، **یک دامنه** (هر دامنه‌ای، حتی ارزان‌ترین)، و **داکر** (که روی سرور نصبش می‌کنیم).

## ۱) سرور رایگان از کجا؟ — وضعیت واقعی Free Tierها (پاییز ۲۰۲۶)

| سرویس | چه می‌دهد | محدودیت مهم | کارت بانکی |
|---|---|---|---|
| **Oracle Cloud Always Free** ⭐ | معادل ۲ هستهٔ ARM (A1) + ۱۲ گیگ رم همیشه‌روشن، ۲ ماشین AMD یک‌گیگی، ۲۰۰ گیگ دیسک | ثبت‌نام فقط با کارت بین‌المللی (برای تأیید هویت، بدون کسر پول) و در همهٔ کشورها فعال نیست | لازم |
| **Google Cloud** | یک ماشین e2-micro (۱ گیگ رم) همیشه رایگان در ریجن‌های آمریکا | ۱ گیگ برای MySQL + لاراول تنگ است؛ باز هم کارت می‌خواهد | لازم |
| **GitHub Codespaces** | ماهی ۶۰ ساعت محیط ابری با داکرِ ازپیش‌نصب | سرویس ۲۴/۷ نیست؛ برای تمرین و دمو، نه هاست دائمی | لازم ندارد |
| **Render** | اجرای کانتینر روی پلن رایگان با HTTPS | بعد از ۱۵ دقیقه بی‌کاری سرویس می‌خوابد و فایل‌سیستم موقت است → برای این پروژه مناسب نیست | لازم ندارد |

**پیشنهاد ما: Oracle Always Free** — جایی پیدا نمی‌کنید که این‌قدر رم و CPU را
«برای همیشه» بدهد. اگر ثبت‌نامش برایتان مقدور نبود، با Codespaces کل این
راهنما را تمرین کنید (بخش ۵) — مهارتش دقیقاً یکی است.

نکته‌های ثبت‌نام اوراکل که جلوی سردرگمی را می‌گیرد:

- **Home Region را هوشمندانه انتخاب کنید** — بعداً قابل تغییر نیست و منابع
  Always Free فقط در همان ریجن ساخته می‌شوند. ریجن‌های پرطرفدار (مثل Ashburn)
  مکرراً خطای «Out of Capacity» برای ماشین‌های ARM می‌دهند.
- علاوه بر Always Free، **۳۰۰ دلار اعتبار آزمایشی ۳۰ روزه** هم می‌گیرید —
  برای امتحان سرویس‌های دیگر OCI، نه برای این راهنما.
- اگر صفحهٔ ساخت ماشین ARM ظرفیت نداشت: صبر کنید و دوباره امتحان کنید
  (معمولاً آزاد می‌شود)، یا ریجن خلوت‌تری هنگام ثبت‌نام انتخاب کنید.

## ۲) آماده‌سازی سرور (Oracle یا هر VPS اوبونتویی)

### ۲-۱) ساخت ماشین

در اوراکل: **Create Instance** با این انتخاب‌ها:

- Image: **Canonical Ubuntu 24.04 LTS** (خودکار ARM/aarch64 است)
- Shape: **VM.Standard.A1.Flex** — ۲ OCPU و ۱۲ گیگ رم (سقف رایگان)
- SSH key: کلید عمومی خودتان (بدون آن وارد سرور نمی‌شوید)

نگران ARM نباشید — همهٔ ایمیج‌های این پروژه (`php:8.3-fpm-alpine`,
`mysql:8.4`, `caddy:2-alpine`) معماری arm64 را پشتیبانی می‌کنند.

### ۲-۲) باز کردن پورت‌ها — تلهٔ معروف اوراکل

فایروال ابر فقط پورت ۲۲ را باز می‌دهد. برای وب باید پورت‌های ۸۰ و ۴۴۳ را
باز کنید: **Instance → Subnet → Security Lists → Add Ingress Rules** برای
`0.0.0.0/0` روی TCP 80 و 443. (نصف عیب‌یابی‌های «سایتم باز نمی‌شود» همین‌جاست!)

### ۲-۳) DNS

جایی که دامنه خریدید، یک رکورد **A** بسازید که به IP عمومی سرور اشاره کند
(مثلاً `shop.example.com → 203.0.113.10`). تا این رکورد جواب ندهد، گواهی
HTTPS صادر نمی‌شود — پس اول DNS، بعد دیپلوی.

### ۲-۴) نصب داکر (روی سرور)

```bash
ssh ubuntu@<IP-سرور>
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && exit   # بعد دوباره ssh کنید
```

## ۳) دیپلوی — دو دستور

روی سرور:

```bash
git clone https://github.com/MSS1625/shop-php.git && cd shop-php

cp .env.production.example .env.production
nano .env.production        # DIGISHOP_DOMAIN + رمزهای قوی دیتابیس
```

سپس:

```bash
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build --wait
```

همین! بوت اول چند دقیقه طول می‌کشد (بیلد ایمیج + مقداردهی اولیهٔ MySQL +
migrate و seed پشت healthcheckها). بعد از آن:

- **`https://دامنهٔ-شما`** بالا است — گواهی Let's Encrypt را Caddy خودش گرفته
  و تمدیدش هم خودکار است؛ HTTP هم خودکار به HTTPS ریدایرکت می‌شود.
- رمز مدیر فروشگاه یک‌بار در لاگ چاپ می‌شود:
  `docker compose --env-file .env.production -f docker-compose.prod.yml logs app`
  (یا از قبل `ADMIN_PASSWORD` را در `.env.production` ست کرده‌اید)
- فقط caddy بیرون در دسترس است (۸۰/۴۳)؛ اپ و nginx و MySQL پشت شبکهٔ داخلی‌اند.

> میان‌بر برای دستورهای طولانی: `alias dc='docker compose --env-file .env.production -f docker-compose.prod.yml'`
> بعدش فقط `dc ps`، `dc logs -f app`، `dc up -d --build --wait` …

## ۴) بعد از دیپلوی

**آپدیت به نسخهٔ جدید:**

```bash
git pull
dc up -d --build --wait    # entrypoint همان shop:install امن را دوباره اجرا می‌کند
```

**بکاپ دیتابیس (هر چند وقت یک‌بار، حتماً):**

```bash
dc exec db sh -c 'exec mysqldump -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"' \
  > digishop-$(date +%F).sql
```

**بکاپ عکس‌های آپلودشده:**

```bash
docker run --rm -v digishop-prod_storage-data:/data -v "$PWD":/backup \
  alpine tar czf /backup/uploads-$(date +%F).tar.gz -C /data .
```

**لاگ‌ها:** `dc logs -f caddy` (گواهی/پروکسی) · `dc logs -f app` (لاراول).

## ۵) تمرین بدون هیچ سروری — GitHub Codespaces

اگر فعلاً به VPS یا کارت بین‌المللی دسترسی ندارید، همین مسیر را رایگان تمرین کنید:

1. روی ریپو، دکمهٔ سبز **Code → Codespaces → Create codespace**
2. در ترمینال مرورگر:
   ```bash
   docker compose up -d --wait    # دقیقاً همان استک (app + web + db)
   ```
3. پورت ۸۰۸۰ را از پنل Ports فوروارد و Public کنید → یک URL زنده دارید.

ماهی ۶۰ ساعت رایگان است و داکر از قبل نصب است — برای یاد گرفتنِ همین
دستورها و healthcheckها کاملاً کافی است؛ فقط سرویس ۲۴/۷ نیست.

## ۶) عیب‌یابی سریع

| نشانه | اولین جایی که نگاه کنید |
|---|---|
| گواهی HTTPS گرفته نمی‌شود | `dc logs caddy` — تقریباً همیشه DNS (بخش ۲-۳) یا پورت ۴۳ بسته (بخش ۲-۲) است |
| سایت باز نمی‌شود ولی Caddy بالا است | `dc ps` — آیا app و web و db همه `healthy`اند؟ بعد `dc logs app` |
| بوت اول طولانی شد | طبیعی است؛ `--wait` پشت healthcheckها منتظر می‌ماند (MySQL init + migrate) |
| لینک‌ها http بودند | از v2.17.0 خودکار درست است (`trustProxies`)؛ اگر نسخهٔ قدیمی‌تر دارید آپدیت کنید |
| `Out of Capacity` در اوراکل | ریجن خلوت‌تر یا تلاش مجدد (بخش ۱) |

## جمع‌بندی

مسیر کامل: **VPS رایگان → داکر → `.env.production` → یک دستور → فروشگاه
روی HTTPS با دامنهٔ خودتان.** اگر این راهنما را قدم‌به‌قدم جلو رفتید، در عمل
یاد گرفته‌اید: Free Tierهای واقعی چطور کار می‌کنند، فایروال ابری و DNS چطور
به هم وصل می‌شوند، Caddy چطور بدون کانفیگ SSL می‌گیرد و یک استک داکری
چطور روی سرور واقعی بالا می‌آید — مهارت‌هایی که روی هر پروژهٔ دیگری هم همین‌طور کار می‌کنند.
